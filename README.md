# 光渡：离线二维码文件传输

光渡通过连续二维码，把文件从一台电脑的屏幕传到另一台设备的摄像头。文件内容不会上传到服务器，也不需要内网和外网互通。

## 快速开始

### 内网发送端

1. 将整个 `qr-airgap-transfer` 文件夹复制到内网电脑。
2. macOS 双击 `start-mac.command`；Windows 双击 `start-windows.bat`。也可以直接双击 `index.html`。
3. 选择“发送文件”，再选择需要传输的文件。
4. 发送端首先显示元数据帧。让接收端识别这一帧后，再点击“开始播放”。

### 外网接收端

1. 在外网电脑上打开同一程序的 `receiver.html`，或通过启动脚本进入“接收文件”。
2. 允许浏览器使用摄像头，把取景框对准内网电脑屏幕。
3. 收齐全部分片后，程序会核对文件大小和 SHA-256；只有校验成功才能下载。

建议使用最新版 Chrome 或 Edge。Safari 也可使用，但不同系统对本地网页摄像头权限的处理不同。如果直接双击页面无法调用摄像头，请使用随附启动脚本。启动脚本会自动选择一个可用端口，并且只监听本机 `127.0.0.1`，不会把页面暴露给局域网。

## 手机接收说明

接收页面本身支持手机摄像头，但手机浏览器通常要求页面来自 HTTPS 或手机本机的可信来源。最稳妥的完全离线方式是使用外网笔记本摄像头。如果需要手机直接接收，可把这套静态页面部署到组织批准的 HTTPS 静态站点；页面代码仍在浏览器本地处理文件，部署服务器不会接触二维码中的文件内容。不要把页面部署到未经审查的第三方站点。

## 大文件如何处理

二维码不是高速通道。默认每帧包含约 1,200 字节，按 250 ms 播放，理论原始速率约 4.8 KB/s；实际速度取决于摄像头、屏幕、距离和漏帧情况。10 MB 文件通常需要几十分钟。为避免浏览器内存耗尽，程序拒绝超过 50 MB 的单个文件；请先拆分大文件。

大文件建议按以下顺序处理：

1. 先用 ZIP、7-Zip 等工具压缩；敏感文件应先用组织批准的工具加密。
2. 将压缩包切成 10–20 MB 的分卷，逐卷传输；每卷单独校验和重试。
3. 保持默认 1,200 字节/帧；识别不稳时降到 800 或 600 字节，并把播放间隔调到 400–700 ms。
4. 收完每个分卷后立即核对 SHA-256，再继续下一卷。

程序会循环播放全部分片，接收端支持乱序接收和重复帧自动去重。漏掉的帧可在下一轮补齐，不需要从头清空。

## 完整性与安全

- 每个二维码数据帧带 CRC32，用于发现扫描错误。
- 完整文件带 SHA-256，用于确认重组后的字节与发送端一致。
- CRC32 和 SHA-256 只保证完整性，不提供保密性或来源认证。
- 任何能看到发送端屏幕的人都可能复制二维码内容。
- 本工具不会绕过单位的数据外传审批、审计或保密制度。

## 文件说明

- `sender.html`：发送端。
- `receiver.html`：接收端。
- `index.html`：角色选择入口。
- `src/`：协议、发送端、接收端和样式。
- `vendor/`：随程序打包的开源二维码库，运行时不访问 CDN。
- `start-mac.command`、`start-windows.bat`：本地启动脚本。

## 开发与验证

需要 Node.js 20 或更高版本：

```bash
npm install
npm test
npm run check
```

运行时依赖固定为 `qrcode-generator 2.0.4`（MIT）和 `jsQR 1.4.0`（Apache-2.0），均已复制到 `vendor/`，最终程序不依赖网络。

## Jenkins + Docker 部署

项目附带 `Jenkinsfile`、`Dockerfile` 和 `docker/nginx/default.conf`，用于把静态站点构建为 Nginx 容器。Jenkins Linux 节点需安装 Node.js 20+ 和 Docker，并配置 `linux-docker` 标签；在 Jenkins 中创建只绑定本仓库的 **Pipeline from SCM** 或 Multibranch Pipeline 任务，脚本路径填写 `Jenkinsfile`，仓库凭据通过 Jenkins Credentials 配置，不要写入仓库。流水线每 5 分钟轮询 SCM，仅部署 `main`、`master` 和 `release/*` 分支，执行静态文件/JS 语法检查，构建并探测镜像后部署；部署健康检查失败时会尝试恢复旧镜像。

默认容器端口绑定到同机 Docker bridge 地址 `172.17.0.1:18081`，与网关项目的 `qr.winter-cloud.xyz` vhost 保持一致。若服务器 bridge 网关不同，需要同步修改 Jenkinsfile 的 `APP_BIND_IP` 和网关 upstream；并确保服务器防火墙不允许外部访问 `18081`。版本号保存在 Jenkins 节点的 `/var/lib/jenkins/qr-airgap-transfer/VERSION`，部署目录需对构建用户可写；默认保留最近 3 个镜像版本。首次发布前，先在网关项目发布 HTTPS vhost、DNS 和有效证书，确保 `Permissions-Policy` 允许本站点使用摄像头，然后再运行本项目流水线。部署服务器必须为接收端提供 HTTPS，网页摄像头才能正常工作。
